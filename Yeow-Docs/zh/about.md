# 关于 Yeow

## 定位

Yeow 是一个面向 **Minecraft** 的插件开发框架：用 **TypeScript / JavaScript** 编写插件，由运行时为每个插件启动**独立的 JS 线程**，通过消息桥与游戏主线程交互。构建产出**平台无关**的插件包（`.yeow.zip`），任何实现平台规范的运行时都能运行同一份插件。

## 设计目标

- **现代工程化**：TypeScript 优先、npm 生态、热重载、构建即产物——把 Web 前端的最佳实践带到 Minecraft 插件开发
- **线程分离**：插件代码不阻塞服务器主线程；每插件独立线程，一个插件崩溃不影响其他插件
- **平台无关**：插件包是纯 ZIP（JS + 资源 + 元信息），不绑定 Java / Bukkit——协议层开放，任何平台可实现运行时
- **原生能力扩展**：Native Service 让插件携带并调用原生程序（Go/Rust/C++），兼顾重计算场景

## 基本原则

Yeow 的核心原则是**避免平台绑定**：插件只依赖协议层（消息通道、任务、事件、权限模型），不依赖任何宿主平台的专有 API。Paper/Bukkit 的 `Yeow` 运行时只是官方实现示例。

### 不提供调用 Java 方法的 API

Yeow **不会**提供从 JS 直接调用 Java 方法的 API。原因：

1. **技术困难**：JS 运行在独立的 QuickJS 线程/上下文中，直接调用 Java 方法需要跨线程的同步桥、对象引用与生命周期管理、类型系统映射——复杂度高且难以保证安全（主线程阻塞、引用泄漏、线程安全）
2. **破坏跨平台兼容性**：允许调用 Java 方法意味着插件代码依赖具体实现（Paper 的类、版本化的 CraftBukkit 包），同一插件无法在其他运行时（其他平台/未来实现）运行——直接违背平台无关的核心原则

需要 Java 侧能力的场景通过**协议层**解决：游戏操作走任务/事件/命令桥；插件间通信走 Service；原生计算走 Native Service；其他 Java 插件可通过 [Java 集成接口](specifications/java-api.md) 调用 Yeow 插件注册的服务。

## 未来规划

### Yeow v1

Yeow v1 只是**概念验证**的成熟产物：受个人能力与时间所限，无法将 Yeow 的全局设想完整实现，只得**割爱择取部分设想**，在一个子领域（**Minecraft 服务端开发**）内聚焦实现。v1 验证的是：JS/TS 编写游戏插件、独立线程、平台无关插件包、协议层开放——这些核心假设在服务端场景的可行性。

### Yeow v2 —— 全栈模组开发（客户端能力）

Yeow v2 将尝试引入**客户端能力**（全栈模组开发）。在 Yeow 的设想中，模组开发被分为**界限分明的两个部分**——服务端与客户端——因为 Minecraft 本身就是经典的 C/S 模型：

- **服务端**处理游戏逻辑
- **客户端**处理本地资源、画面渲染、音效、按键操作

关键设计：

- **插件的客户端部分与服务端部分跑在不同的 JS 线程上**，二者通过**标准化的网络通信**交流
- **对单人游戏一视同仁**：Minecraft 单人模式本质上是启动了内部的集成服务端——Yeow 提供一种新的方式结束此前模组开发的混乱（逻辑端/物理端割裂），**规避"单人模式正常、放在服务器上就崩溃"**（混淆了客户端专有类）的情况
- **部署即裁剪**：一个模组在服务端上只运行服务端部分，在客户端上只运行客户端部分；单人游戏中，二者在不同的线程中**同时运行**
- **绝不包办**：Yeow 不会尝试做大而全的"包办"（例如允许操作渲染管线），而是提供**基础而常用的接口**（按键监听、HUD 渲染、客户端音效等），底层场景仍交给原生开发
- **项目结构**：类似 `server/` 与 `client/` 两目录，开发者分别引入 `@yeow/server-api` 与 `@yeow/client-api`
- **构建产物**：仍为 `.yeow.zip`——**Yeow v1 的插件可视为仅包含服务端部分的模组**

### WASM 原生支持

Yeow 正在尝试引入 **WASM**：解决 JS 在特定场景下**性能不足**的问题，并探究**高效的互操作方案**（平台层 ↔ WASM 模块）以及**依赖包集成方案**（npm 包携带 `.wasm` 产物），为未来的高性能场景做准备。

### Yeow Client Lite —— 通用客户端能力

Yeow 在 v1 到 v2 的过渡期间考虑开发 **Yeow Client Lite**（客户端模组）并**标准化规范**，在不同平台提供一致的接口（绘制简单 HUD、监听客户端按键等），供服务端调用：

- 只要一个客户端安装了 Yeow Client Lite，**在任何服务器**中都能享受客户端能力增强（如果存在对应的 Yeow 插件）
- 在 Yeow v1 与 v2 的服务端开发中，可以使用基于 Yeow Client Lite 提供的**通用客户端能力**，而无需专门开发客户端

## 开放与标准

Yeow 的目标是成为 **Minecraft 的 Web 标准**：一个开放、跨实现、可持续演进的插件开发标准。任何平台都可以实现一个运行时，运行同一份插件。

## 愿景

Yeow 的愿景是构造**面向未来的、开放的、属于所有人的创造入口**。

**YEOW = Your Entry to an Open World。**
