## Yeow v1（当前）——概念验证

**v1 只是概念验证**：受个人能力与时间所限，无法将 Yeow 的全局设想完整实现，只得割爱择取部分设想，在子领域（Minecraft 服务端开发）内聚焦实现。规划：

### 更完善的 API 和事件覆盖面

扩展 yeow-api 与运行时任务/事件桥的能力边界

### 开发调试工具

增强插件开发与运行时的诊断体验：

- 运行时调试器（断点 / 单步 / 变量查看）——开发模式下使用 Node.js（V8）执行 JS，获得完整的调试器能力
- 可视化工具：调度器任务队列 / 消息队列的实时视图

### Folia 支持

Yeow 运行时尝试适配 [Folia](https://github.com/PaperMC/Folia)

### 优化：任务调度器与事件分发机制

- 降低主线程的负担

## Yeow v2 —— 全栈模组开发（客户端能力）

Yeow v2 将尝试引入**客户端能力**。在 Yeow 的设想中，模组开发被分为界限分明的两个部分——**服务端**与**客户端**（Minecraft 本身就是经典的 C/S 模型）：服务端处理游戏逻辑，客户端处理本地资源/画面渲染/音效/按键操作。

- **插件的客户端部分与服务端部分跑在不同的 JS 线程上**，二者通过**标准化的网络通信**交流
- **对单人游戏一视同仁**（单人模式本质上是内部集成的服务端）——用新方式结束模组开发此前的混乱（逻辑端/物理端），**规避"单人模式正常、放在服务器上就崩溃"**的情况
- **部署即裁剪**：模组在服务端只运行服务端部分，在客户端只运行客户端部分；单人游戏中二者在不同线程**同时运行**
- **绝不包办**：不尝试大而全的"包办"（如操作渲染管线），只提供**基础而常用的接口**（按键监听、HUD 渲染、客户端音效等）
- **项目结构**：类似 `server/` 与 `client/`，开发者分别引入 `@yeow/server-api` 与 `@yeow/client-api`
- **构建产物**：仍为 `.yeow.zip`——**Yeow v1 的插件可视为仅包含服务端部分的模组**

## Yeow Client Lite —— 通用客户端能力

开发 **Yeow Client Lite**（客户端模组）并**标准化规范**，在不同平台提供一致的接口（绘制简单 HUD、监听客户端按键等），供服务端调用：

- 只要一个客户端安装了 Yeow Client Lite，**在任何服务器**中都能享受客户端能力增强（如果存在对应的 Yeow 插件）
- 在 Yeow v1 与 v2 的服务端开发中，可使用基于 Yeow Client Lite 的**通用客户端能力**，无需专门开发客户端
